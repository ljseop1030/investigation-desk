## P1 · 콘텐츠 분리 — 완료

프로토타입은 단일 파일에 상수·UI·게임 로직이 전부 섞여 있었다. 사건을 하나
추가하려면 코드를 고쳐야 했고, 코드가 캐릭터를 `'kang'` 같은 id로 직접
참조하고 있어 시나리오를 바꾸면 곳곳이 깨지는 구조였다.

```
content/                      ← gitignor
  cases/{1187,1204,1215}/{case,polnet,records,form}.js
  characters/{baek,kang,yoo,kim,won,k,notice}.js
  screen/{apps,notes,org,terminal}.js
  polnet.js  notices.js  story.js
client/
  content-loader.js
  ui/strings.js
shared/enums.js
```

### 왜 이렇게 나눴나

**사건 단위 폴더** — 추가는 폴더 하나, 삭제는 폴더 삭제. 로더가 glob으로
모으므로 코드도 로더도 건드리지 않는다. P7에서 시나리오를 갈아엎을 때
폴더째 교체하기 위해서다.

**id 재설계** — 기존 `v1`~`v10`, `a1`~`c8`은 사건도 카테고리도 섞여 있어
읽을 수 없었고 배열 순서와도 어긋나 있었다(`v6`이 1204인데 `v5`·`v7` 사이).
사건번호를 접두사로 두고 의미 있는 이름을 붙였다. 슬래시 대신 하이픈을 쓴 것은
P5에서 `/api/records/:id` 라우팅에 그대로 쓰기 위해서다.

**`case` 필드는 명시적으로** — 로더가 경로에서 뽑아 붙일 수도 있었지만, 파일을
열었을 때 어느 사건인지 바로 보이는 쪽을 택했다. 로더도 그만큼 단순해졌다.

**로더는 `client/`에** — `content/`를 통째로 gitignore하려면 그 안에 코드가
있으면 안 된다. 로더는 데이터가 아니라 코드다.

**`private` 키** — 클라이언트에 내려가면 F12로 게임이 끝나는 것들을 한 키
아래 모았다. 판단 기준은 "플레이어가 정상 진행으로 결국 보게 되는가, 그 절차
자체가 게임인가". CCTV 수집 목록처럼 처음부터 열려 있는 자료는 공개.
파일을 나누지 않은 것은 서버가 아직 없어서 옮길 곳이 없기 때문이다. 경계 판단은
끝냈고 P5에서 `delete r.private` 한 줄로 공개본을 만든다.

**trait** — 코드가 캐릭터 id를 직접 보던 부분을 걷어내기 위해서다. 코드 경로가
갈리는 것만 넣었다(`HIDDEN` `BROADCAST` `EXTERNAL` `BURNABLE`). 답장 지연이나
말풍선 개수처럼 값만 다른 것은 `style`, 말투·태도처럼 LLM만 읽는 것은 persona.
원 화의 대본은 trait 없이 `script` 필드 존재 여부로 분기한다.

> trait이 부적절해지면 전환 비용은 낮다. 읽는 곳이 `core/rules/story.js`와 UI
> 몇 군데뿐이라서다. 다만 **캐릭터 id를 코드에 직접 쓰지 않는다**는 규칙만은
> 지켜야 한다. 그게 깨지면 어떤 구조를 택하든 전환이 비싸진다.

**story.js** — K 등장·소각과 강윤하의 추궁은 두 캐릭터에 걸쳐 있어 어느 캐릭터
파일에도 넣을 수 없었다. 강윤하는 K를 모르고, K가 강윤하 대사를 갖는 것도
이상하다. 판단 기준은 **"코드가 알아야 하는가"**다.

| | persona | story.js |
|---|---|---|
| 읽는 주체 | LLM | 코드 |
| 결과 | 말풍선 내용만 다름 | 상태 변화·예약·잠금 |
| 예 | 유현욱이 강 경위 얘기에 무름 | K가 사라져 입력창이 잠김 |

**시간 단위** — 콘텐츠에서 코드를 부를 수 없으므로 `sec()`/`min()` 헬퍼를
걷어내고 전부 초 단위 숫자로 적었다. `TEMPO` 배속은 `adapters/clock.js`에서.

```
read: [min(8), min(20)]  →  read: [480, 1200]
```

**UI 문구 분리** — `client/ui/strings.js`. P9(번역) 때문이며 지금 하지 않으면
나중에 전수 조사가 된다. 세계관 텍스트(부팅 화면, 단말 공지, 계정 안내)는
번역 대상이 아니라 **교체** 대상이므로 `content/screen/`에 남겼다.

> 기준은 맞았는데 파일 안에서 지켜지지 않았다. 극중 시스템이 하는 말과
> 세계관 사실(내선번호 등)이 `strings.js`에 섞여 들어갔다. **P4-1에서 다시 갈랐다.**
> 받는 자리는 `content/screen/systems.js`.

## P2 · core + 테스트 + CI — 완료

게임 로직을 브라우저 밖으로 꺼냈다. `npm test`가 브라우저도 콘텐츠도 없이
브라우저 없이 통과하고, `npm run dev`에서 실제 콘텐츠로 대화가 오간다.
(P2 종료 시점 61개, P3에서 80개.)

**브랜치** `feat/p2-core` → `chore/p2-ci-docs`

계획은 `feat/core-scheduler` → `feat/core-rules` → `ci/setup` 셋이었으나,
스케줄러와 규칙은 나눠도 리뷰 단위가 되지 않아 하나로 합쳤다. CI만은 떼어
두었다. 워크플로를 추가한 PR이 첫 status check 대상이라, 코드가 섞여 있으면
빨간불의 원인을 좁히기 어렵다.

```
core/ DOM·fetch를 import하지 않는다
scheduler.js 절대시각 큐
state.js 진행 상태
events.js UI가 구독할 자리
actions.js 규칙과 스케줄러를 잇는다
rules/ chat · records · forms · story
adapters/clock.js now()만 있는 최소 어댑터
test/ 단위 49 + 흐름 통합 12
```

### 프로토타입에서 바꾼 것

**예약을 하나의 큐로 통합.** 계획은 `{ msg, pushes, db }` 세 종류를 그대로
가져오는 것이었다. 그런데 셋이 같은 모양이 아니었다. `db`와 `pushes`는 순수한
예약인데 `msg`는 예약(`readAt`, `replyAt`)과 대화 상태(`queue`, `working`)를
한 봉투에 담고 있었다. 스케줄러가 대화 개념까지 알아야 해서 테스트를 쓰려면
대화를 끌고 와야 했다. 예약만 `{ kind, at, ...payload }` 하나로 합치고 상태는
`state.js`로 뺐다. 스케줄러는 "시각 되면 알려주는 물건"이 됐다.

**답장 타이머는 첫 메시지에 잡고 유지한다.** 프로토타입은 전송할 때마다
타이머를 다시 잡아, 재촉할수록 답장이 뒤로 밀렸다. 강윤하처럼 `burstWait`이
긴 캐릭터는 무한히 미뤄질 수 있었다. 재촉을 벌주는 셈인데 화면에는 침묵만
보이므로 플레이어에게 전달되지 않는 벌이다. 기다림의 길이는 캐릭터가 정하고
플레이어 행동이 그걸 바꾸지 못하게 했다.

답장을 기다리는 중에 또 보내면, `burst`는 잡혀 있던 시각에 모아서 한 번에
답하고, 아닌 캐릭터는 앞 답장 뒤에 20~60초 간격으로 이어 붙는다. 이미 폰을
든 상태이므로 처음부터 다시 재지 않는다.

**양식 채점을 큐에 태웠다.** 프로토타입은 `setTimeout`으로 돌렸는데
`status: 'review'`는 저장됐다. 제출하고 창을 닫으면 그 양식은 영원히
"검토 중"에 갇혔다. 성격이 `db` 해금과 같아서(시각 되면 상태 하나 바꾼다)
같은 큐에 넣었다.

**`TEMPO`는 `clock.js`가 아니라 `rules/`에서 적용한다.** 계획은 clock이었으나
배속은 브라우저의 성질이 아니라 게임 설정이고, "범위에서 무작위로 뽑기"도
시계가 할 일이 아니다. `now()`는 배속 없는 절대시각으로 두어야 저장된 예약과
다음 세션의 `now()`가 어긋나지 않는다.

**시계와 난수를 주입받는다.** 처음에는 `clock.js`에 `advance()`를 두고
"테스트 전용" 주석을 달았다. 그러면 배포되는 코드에 시간을 조작하는 함수가
남고, 모듈 전역 `offset` 때문에 테스트끼리 오염된다. 가짜 시계를
`test/helpers/`로 옮기니 둘 다 사라졌다. `random`도 같은 이유다. 고정하지
못하면 경계 조건을 테스트할 수 없다.

결과적으로 `adapters/clock.js`는 한 줄이 됐다. 부실해서가 아니라 어댑터가
원래 그런 물건이라서다.

**`core/rules/forms.js` 추가.** 계획 파일 목록에 없었는데 테스트 항목에는
"채점: 날짜/번호 표기 변형"이 있었다. 프로토타입에서 `submit()` 안에 인라인으로
있던 것이라 집이 없었다.

**`canRequest`가 record 객체 대신 id를 받는다.** `validDeliveries`와 인터페이스를
맞췄고, 없는 id에 대한 방어가 덤으로 생겼다.

### 프롬프트 인젝션 방어를 앞당겼다

LLM이 `delivers`로 준 키를 그대로 믿지 않는다. 실재하는 자료인지, 그 사람
소관(`provider`)인지, 제한열람을 우회하는 건 아닌지 확인한다. P1에서
`content/records.js`에 `provider`를 이미 넣어둔 덕에 P5+ 예정이던 대조를
지금 할 수 있었다.

유현욱이 차적 조회(김주원 소관)를 등록하겠다고 해도, 변사자 인적사항을
메신저로 내려주겠다고 해도 걸러진다. 페르소나가 흔들려도 게임은 안 깨진다.

> 다만 이 방어는 **가짜 응답으로만 검증됐다.** 진짜 모델이 무엇을 뱉는지는
> P5-a에서 처음 본다.

### 고친 버그

- **답장이 읽음보다 먼저 도착할 수 있었다.** `read` 범위를 두 번 따로 굴렸다.
  강윤하 기준 읽음 굴림 1200초, 답장 굴림 480초면 답장이 먼저 온다. 읽음을
  먼저 정하고 거기서부터 답장을 잰다.
- **이름 판정이 한국어 조사를 놓쳤다.** 정규식 뒤 경계에 한글이 있어 `K가`,
  `K한테`가 안 걸렸다. 띄어쓴 `그 K 말이에요`만 잡혔다. 경계를 라틴문자·숫자로
  좁혔다.

디테일 수정
- **burst 캐릭터는 답장이 계속 밀렸다.** 이어붙임 조건이 `!burst`라 정상 계산
  경로로 빠졌다. 단위 테스트가 이 동작을 정답으로 알고 통과시키고 있었다.
- **추궁이 시작돼도 답장 예약이 살아 있었다.** 소각 대사 세 줄 뒤에 원래
  답장("아이고 이제 봤네요")이 뒤늦게 도착했다.

앞의 둘은 프로토타입에서 그대로 옮겨온 것이고, 뒤의 둘은 이번에 들어갔다가
흐름 통합 테스트와 콘솔 확인에서 드러났다.

### 테스트

**흐름 통합 테스트가 값어치를 했다.** 조각 테스트 49개가 전부 통과하는 상태에서
burst 문제가 나왔다. 1초씩 시간을 감으며 `tick()`을 돌려 실제 게임과 같은
순서로 재현하니, 단위 테스트가 못 보는 상호작용이 드러난다.

처음 돌렸을 때 네 개가 깨졌는데 원인은 하나였다. **답장을 기다리는 것도
"아무것도 안 하는" 상태라 K가 끼어들어 말풍선이 섞였다.** 코드가 맞고 테스트가
틀린 경우다. K를 다루지 않는 테스트는 `afterIdleSec`을 크게 두어 끈다.

콘솔 확인(`npm run dev`)은 통합 테스트가 못 잡는 것을 잡는다. 픽스처가 아니라
실제 `content/`가 뱉는 데이터로 도는지가 여기서 처음 검증된다.

## P3 · UI — 완료

**결정 — React 유지.**

### 함정 하나 — 사본이 아니라 투영

core는 배열을 제자리에서 민다(`log(cid).push(...)`). React가 그 배열을 직접
들고 있으면 참조가 안 바뀌어 재렌더가 안 걸린다. `useSyncExternalStore`도
같은 이유로 헛돈다.

그래서 React 상태는 core 상태의 **사본이 아니라 투영**이다. 첫 프레임만
`view`로 읽고 그 뒤로는 이벤트로만 채운다.

> **`setState`는 `events.on` 콜백 안에서만 부른다.**
> 사용자 입력은 전부 `actions.*`로 나가고, 돌아오는 건 이벤트뿐.
> 단방향이면 사본이 아니라 화면이다.

`chats`만은 사본을 만들어 넣는다. `[...(c[cid] ?? []), {...m}]`.

### 배선 규칙

- UI는 `actions.*`를 호출하고 `events.on()`으로 받는다. 상태를 직접 고치지 않는다
- 첫 프레임만 `view`로 읽는다. 그 뒤로는 이벤트
- 구독은 `GameProvider` 한 군데. 컴포넌트마다 `events.on`을 부르기 시작하면
  해제를 셀 수 없어진다
- `state.get().screen`에 쓰지 않는다. 화면 배치는 `useScreen`이 들고 있는다
- 캐릭터 id를 코드에 직접 쓰지 않는다. `TRAIT`으로 갈린다

프로토타입 팔레트를 그대로 이사만 온 상태였다. 회색 플랫에 시스템 폰트라

### 결정 — 껍데기는 레트로 OS, 내용물은 건조하게

원본 · 레트로 · 현대 세 시안을 놓고 골랐다.

레트로를 고른 이유는 노스탤지어가 아니라 **거리감**이다. 플레이어는 남의 자리에
앉아 남의 시스템을 더듬는다. 화면이 내 것처럼 느껴지면 그 감각이 안 생긴다.
시대감이 거리감을 만든다.

그리고 더 정확하다. 한국 공공기관 내부망은 지금도 그 시절 UI로 돌아간다.
2024년 사건을 다루는 화면이 2010년쯤에 멈춰 있는 건 시대착오가 아니라 사실이다.
목표는 1999년 윈도우가 아니라 **갱신이 멈춘 공공기관 내부망**이다.

> **경계** — 창틀·작업표시줄·아이콘·로그인 화면은 시대감을 짊어지고,
> 문서·양식·대화 내용은 흰 종이에 검은 글씨로 둔다. 베벨을 콘텐츠 영역까지
> 밀면 장난감이 된다. 사람이 오래 들여다보는 영역은 조용해야 한다.
> 설렘은 부팅 화면과 바탕화면에서 받고, 작업 중에는 방해하지 않는다.

### 곁들여 생긴 것

- **상태 표현.** 인라인 스타일이라 `:hover` `:active` `:focus-visible`가 한 줄도
  없었다. CSS 파일로 옮기면서 처음 생겼다. 화면이 죽어 보이던 가장 큰 원인이다.
- **초점은 `:focus-visible`로만.** 키보드로 왔을 때만 점선이 보인다. 마우스
  클릭에 점선이 남으면 지저분하다.
- **`prefers-reduced-motion` 존중.**
- **대비.** `hint`를 `#98A2AB` → `#79838C`. 흰 종이 위에서 안 읽혔다.
- **아이콘.** 보편 은유(지구본·원통·클립보드·말풍선)를 이 기관이 실제로 쓰는
  물건(게시판·캐비닛·양식지·겹친 창)으로 바꿨다. 32px 격자, 정수 좌표,
  `crispEdges`. 지구본은 세계관상으로도 틀렸다. 폴넷은 인트라넷이지
  인터넷이 아니다.
- **바탕화면 그라데이션 제거.** 그 시절 바탕화면은 단색이었다.
- **자물쇠 이모지 제거.** OS 폰트에 이모지가 없던 시절이다.
- **스크롤바.** 브라우저 기본 스크롤바는 이 화면이 웹페이지라는 걸 드러내는
  유일한 물건이었다. Firefox는 `::-webkit-` 규칙을 안 받아 기본이 나온다.
- **로그인 화면의 기관명.** 앱마다 `org`가 달라서, 로그인 화면 넷을 지나는 동안
  이 시스템들이 서로 다른 데서 왔다는 게 문장 하나 없이 드러난다.
  **다만 지금 안 그려진다** — `apps.js`에 `org` 필드가 없고 `org.js`의
  `AGENCY`/`STATION`도 아무 데서도 안 쓰인다. P4-1에서 발견, 판단 보류. 상자 안에
  제목 막대를 세웠다가 물렸다 — 창 제목 막대와 똑같이 생겨서, 층이 둘로 읽히지
  않고 창이 겹쳐 그려진 것처럼 보였다.
- **인물 목록의 템포 라벨 제거.** `한참 뒤에 길게` 같은 문구는 게임이 답을 미리
  알려주는 것이었다. 강윤하가 늦는다는 걸 기다려보고 알아채는 게 이 게임이다.
  콘텐츠의 `tag` 필드는 캐릭터 정의를 읽을 때의 메모로 남겨뒀다.
- **기한 표시 제거.** 콘텐츠의 `due`는 남겼다. 강윤하가 대화에서 언급할 때
  근거가 되는 값이라 화면에서만 뺐다.
- **창이 언제나 포스트잇 위.** z 대역을 갈랐다. 창 1000+, 포스트잇 10대.
- **포스트잇 색을 바랜 사무용으로.** 원래 팔레트는 이 화면에서 혼자 알록달록했다.

## P4 · 문구 정리 + 서브모듈 + 세이브 + 배포 — 진행 중

**AI는 여기 없다.** 아직 어디에도 붙이지 않았고, 모든 대화는 캐릭터 `fallback`
대사로 돈다(`ai.reply`가 즉시 throw). 이 상태로 배포한다.

**미루는 이유** — P4에는 처음 하는 위험한 일이 이미 둘이다. 프라이빗 서브모듈을
호스팅이 받게 만드는 것, 그리고 배포 파이프라인 자체. 여기에 API 키와 서버리스
함수까지 얹으면 빨간불이 떴을 때 후보가 넷이 된다.

```
1  문구 분류 정리          완료   chore/p4-strings
2  content 서브모듈 승격   완료   chore/p4-submodule
3  storage + 복원          완료   feat/p4-save
4  복원 검증               완료   (3과 같은 브랜치)
5  다듬기                         chore/p4-polish
6  배포                           chore/p4-deploy
```

계획에 없던 `p4-polish`가 하나 늘었다. 배포 준비(TEMPO·폰트)와 연출 손질(첫
팝업 순서, 각종 딜레이)은 성격이 다르다. 나중에 "배속이 왜 이러지"를 쫓을 때
`p4-deploy`만 보면 되는 편이 낫다.

### 1. 문구 분류 정리 — 완료

P1에서 세운 기준(**번역** 대상은 `strings.js`, **교체** 대상은 `content/`)은
맞았는데 파일 안에서 지켜지지 않았다.

**판별 질문** — 시나리오를 통째로 갈아엎어도 이 문장이 그대로 남아도 되는가.

| | 예 | 어디로 |
|---|---|---|
| 앱 크롬 | 제출 · 확인 · 뒤로 · 전송 · 아이디 · 비밀번호 · 오전/오후 | `strings.js` 유지 |
| 극중 시스템의 말 | 반려 사유, 조회 이력 안내, 발신전용 안내, 등록된 자료 없음 | `content/screen/systems.js` (신설) |
| 세계관 사실 | 내선번호, 자산번호 | `content/screen/terminal.js`, 중복 제거 |

**전부 `content/`로 몰지 않은 이유** — 다음 항목에서 `content/`가 프라이빗
서브모듈이 된다. UI 문구까지 넣으면 서브모듈 없이는 버튼에 글자가 없는 저장소가
된다. 지금은 콘텐츠가 없어도 껍데기는 뜬다. 그 성질이 CI(콘텐츠 없이
`npm run check`)와 P12의 라이선스 분리에 걸려 있다.

**역방향으로 하나 왔다.** `introFootnote`의 "진행 상황은 이 브라우저에 자동
저장됩니다"는 세계관이 아니라 게임이 자기 자신에 대해 하는 말이다. P4-3에서
참이 되고 P10에서 다시 바뀐다. `strings.meta.autosave`로.

**템플릿 함수를 자리표시자로.** `(n, max) => \`…\`` 열몇 개를
`'…({n}/{max}회…)'` + `client/ui/format.js`의 두 줄짜리 `fmt()`로. P9에서 파일을
통째로 넘길 수 있다.

**곁들여 닫은 것**

- **계정·비번이 두 군데에 있었다.** 포스트잇(`notes.js`)과 앱 정의(`apps.js`)에
  같은 값이 적혀 있어, 한쪽만 고치면 게임이 안 깨진 채 로그인만 조용히 막힌다.
  포스트잇이 `ref`로 앱을 가리킨다
- **자산번호 중복** (P7 항목이었다), **`alertFrom: 7`** 손으로 센 인덱스
- **포스트잇 색이 콘텐츠에 있었다.** 아이콘은 코드에 있는데 색은 콘텐츠라 기준이
  반대였다. 콘텐츠는 `tone` 이름만, 색은 CSS
- **`collector.requestedBy(who, due)`** — `due`를 받고 안 썼다. P3.5 흔적

**드러난 것** — `AGENCY`/`STATION`이 아무 데서도 안 쓰이고, 그걸 쓸 자리인
`LoginGate`의 `app.org`가 콘텐츠에 없어 영영 안 그려진다(P3.5 참조). 판단 보류.

**한 번 헛디뎠다.** 미사용 문구 키를 보고 바탕화면의 `병행사건 3건` 표시를
"이사 중 빠진 것"으로 단정해 되살렸는데, 의도적으로 뺐던 것이었다. 미사용이
곧 실수는 아니다. 뺀 것은 뺐다고 적어두지 않으면 다음에 또 살아난다.

### 3. `adapters/storage/local.js` + `state_json` — 완료

진행·예약·화면을 한 덩어리로 저장한다. 따로 저장하면 어긋난 순간에 창이 닫혔을
때 진행은 앞서 있는데 예약은 뒤처진 상태가 된다.

**DB는 P10.** 지금 사용자는 한 명이고 브라우저 하나다. 서버 저장이 주는 이득은
다른 기기와 브라우저 청소 둘뿐인데, 대가로 계정·인증·DB가 줄줄이 딸려온다.
게다가 "진행"의 모양이 아직 안 굳었다. 어댑터로 감싸뒀으니
`adapters/storage/server.js`가 옆에 서면 import 한 줄이 바뀐다.

**언제 저장하나** — 3초마다 스냅숏을 떠보고 지난번과 다르면 쓴다. 탭을 닫거나
숨기면(`pagehide`/`visibilitychange`) 강제로 한 번 더. 예약은 스케줄러 안에 있어
React가 모르기 때문에 변화 감지로는 안 잡힌다. 더러움 플래그를 손으로 관리하는
것보다 문자열 비교가 틀릴 여지가 적었다.

**저장이 만들어낸 새 실패 모드**

- **AI 호출 중에 끊기면** `working: true`가 저장되고 그 사람은 영영 입력 중이다.
  세탁만으로는 부족했다. `pending`은 호출 직전에 비워지므로 내가 보낸 말이 아무
  데도 없이 사라진다. **로그 끝의 연속된 내 말을 되찾아** 답장을 다시 건다
- **복원하면 `seq`가 0부터 다시 시작**해 저장된 예약과 id가 겹친다. 지금은
  `cancel`이 객체 동일성으로 비교해 안 터지지만, id로 취소하는 코드가 하나 생기면
  조용히 엉뚱한 걸 지운다. 저장된 id에서 seq를 잇는다
- **깨진 세이브**와 **저장 실패**는 삼킨다. 시크릿 모드에서 localStorage는 그냥 던진다

**함께 처리한 것** — 작성 중인 양식 값(`progress.forms[id].draft`, 제출 시에도
보존), 화면 배치(`useScreen.snapshot()`), 포스트잇 좌표 id 기준화.

**세이브 버전은 1.** 다르면 조용히 버리고 새로 시작한다. `forms`에 `draft`가
늘었지만 없어도 `?? {}`로 받으므로 올리지 않았다.

**`처음부터`는 지우고 새로고침한다.** `state`와 `scheduler`가 모듈 최상단에서 한
번 만들어지는 구조라 setter를 손으로 되돌리는 것보다 확실하다. 버튼 위치와 방식은
나중에 바뀔 예정이라 지우는 일만 `wipe()` 한 군데에 모아뒀다.

**안 한 것** — 로그 자르기. `save.bytes()`로 크기만 볼 수 있게 해뒀다. 대화
로그가 어디까지 커지는지는 굴려봐야 안다. localStorage는 5MB 근처.

### 4. 복원 시 예약 당기기 검증 — 완료

`scheduler.restore()`는 P2에서 만들고 테스트도 있었지만 **프로덕션 호출부가
없었다.** 저장이 붙으면서 처음 실제로 돌았다.

10분 자리를 비운 상황으로 왕복시켜 확인한 것:

```
working 세탁      pending이 비어 있어도 로그에서 내 말을 회수
지난 예약 당김    10분 전에 만기된 read → 지금+800ms
미래 예약 보존    1시간 뒤 push는 그대로
답장 재예약       끊긴 대화에 reply가 다시 걸림
id 충돌 없음      복원 후 새 예약이 기존 뒤 번호로 발급
깨진 세이브       null 반환, 새 게임으로
```

`reply`만 AI를 타는데 지금은 throw → fallback으로 같은 큐를 탄다. 즉 **기다림의
연출은 이 배포물로 전부 확인된다.**

> 세탁과 seq 복원은 아직 테스트가 없다. 위 왕복 검사를 `core/state.test.js`와
> `core/scheduler.test.js`로 옮길 것. 저장이 붙은 뒤로 core에 새 실패 모드가
> 생겼는데 지금은 아무도 안 지키고 있다.

## P5 · AI proxy + 재배포

**이 프로젝트에서 한 번도 실행된 적 없는 경로가 여기다.**
persona 조립 → 모델 호출 → JSON 파싱 → `validDeliveries` → `bubbleTimes`.
테스트는 전부 가짜 응답으로 통과했고, 진짜 모델이 무엇을 뱉는지는 아무도 못 봤다.

여기서 나올 문제는 배포 문제가 아니라 프롬프트 문제다. 말풍선 개수를 안 지킨다,
마크다운을 뱉는다, `delivers`에 없는 키를 넣는다, 유현욱이 갑자기 친절해진다.
배포가 잘 돌아가도 그대로 남는다. 그래서 만드는 것과 배포하는 것을 나눈다.

**브랜치** `feat/p5-ai` → `chore/p5-deploy`

### 5a. 로컬에서 한 번 돌린다

1. `adapters/ai/index.js` — 인터페이스 먼저. 구현체는 뒤에
   - 지금 호출부는 `ai.reply(cid, log(cid))`로 로그 객체를 통째로 넘긴다.
     계획의 `{ characterId, history }`와 다르다. 연속 user 메시지 병합을 어디서
     할지도 함께 정할 것 — 프롬프트 조립이 서버 몫이면 병합도 서버다
   - **`fallback`이 `character.private`에 있다.** private을 벗겨 서버로 올리면
     클라이언트 폴백이 같이 사라진다. 폴백은 서버가 죽었을 때 쓰는 물건이라
     클라이언트에 남아야 한다. 계정·비번과 함께 예외 목록에
2. `POST /api/chat` 서버리스 함수
   - 받는 것 `{ characterId, history }`
   - 서버가 persona 조립 → LLM 호출 → 검증 → 반환
3. Gemini 구현체. `responseSchema`로 JSON 강제하면 파싱 방어 코드가 사라진다
4. 실패 시 캐릭터 `fallback` 대사로 폴백 (P4까지의 상태가 그대로 폴백이 된다)
5. 로컬에서 함수까지 돌려본다(호스팅 CLI). 키는 `.env`

### 5b. 응답 검증 3종 (빠뜨리기 쉬움)

- `messages` 개수 자르기
- `delivers`가 유효한 record id인지 — 안 하면 프롬프트 인젝션으로 임의 해금
  (P2에서 `validDeliveries`로 이미 막아뒀다. 여기서 처음 실물로 시험한다)
- 마크다운·불릿·이모지 후처리 제거

### 5c. 재배포

- 키가 프론트 번들에 없는지 확인
- 환경변수를 호스팅으로 옮기는 일만 남아야 한다
- **P4에서 미룬 `working[cid]` 복원 확인.** LLM 호출 중에 창을 닫고 다시 열어
  입력 중 표시가 영영 켜져 있지 않은지 본다

**완료 기준** 키가 프론트 번들에 없고, 캐릭터가 페르소나대로 답한다.

> **개발 배포의 의미.** P4·P5의 배포는 파이프라인 검증이지 공개가 아니다.
> URL 하나가 생기고 혼자 쓴다. 공개는 P12다.

## P5 이후 · 자료를 레코드로 통합

persona 안에 자료 내용과 `delivers` 키가 그대로 박혀 있다. `scope`와 이중
관리가 되고, id를 바꾸면 두 군데를 고쳐야 한다. 또 메신저로만 주는 자료
(강윤하의 신고접수 원부·CCTV 판독·1215 피해집계, 김주원의 지문대조·장물조회,
백유림의 진정 접수번호)가 records에 없어 어디서도 한눈에 안 보인다.

**바꿀 방향**

- `ACCESS.NONE` 추가 — DB 목록에 안 나타나고 사람한테서만 얻는 자료
- `provider` / `delivery`(`'register'` | `'tell'`) 필드로 표현
- 서버가 `provider`로 필터해 프롬프트를 조립 → persona는 태도만 남는다
- `scope` 제거. `provider`로 계산된다
- K는 예외. 모든 자료 접근이라 별도 처리 필요

**부수 효과** — 자료 단위 수령 기록이 생기므로 아래 문제도 같이 풀린다.

> **K 발설 판정이 헐겁다.** 현재 강윤하 메시지 본문을 문자열로 검사한다
> (`story.js`의 `providedMarkers`). 강윤하가 다르게 표현하면 놓치고, 우연히
> 언급만 해도 준 것으로 친다. 자료 단위 수령 기록으로 교체할 것.
> 코드에 `TODO(P5+)` 주석 있음.

**지금 안 하는 이유** — 프롬프트 조립기가 서버에 있어야 하는데 P5 전엔 서버가
없다. persona가 덜 구체적이 되므로 LLM이 자동 생성 블록을 얼마나 잘 소화하는지도
P6 튜닝에서 확인해야 한다.

## P6 · 프롬프트 튜닝 · 모델 비교

  - 말풍선 개수 지시를 덜 지킴 → 서버에서 자르는 방어 유지
  - 서식 금지를 덜 지킴 → 후처리 필터 유지

- **P8 준비**: 어떤 응답이 사실상 고정인지 관찰해 둔다. 그게 스크립트로 뺄 후보다

## P8 · 하이브리드 대화

비용 대책. **어댑터 앞 분기 하나로 끝나지 않는다.**

```js
export async function reply({ characterId, history }) {
  const scripted = matchScript(characterId, lastMessage(history));
  return scripted ?? await callServer({ characterId, history });
}
```

호출부는 이 모양이지만 `matchScript()` 안이 어렵다. 자유입력이라 "감식 자료
주세요"가 어떤 형태로 들어올지 알 수 없다. 정규식으로는 한계가 있다.

**현실적인 선택지**

| | 방법 | 비용 절감 | 난이도 |
|---|---|---|---|
| A | 저렴한 모델로 의도 분류 후 스크립트 | 큼 (토큰 1/10) | 중 |
| B | 매칭 포기, 히스토리 축소·상한·캐싱으로 절감 | 중 | 낮음 |
| C | 확실한 것만 스크립트 (인사·감사·원 화·발신전용) | 20~30% | 낮음 |

**P6이 먼저인 이유** — 로그를 봐야 어떤 입력이 실제로 오는지 알 수 있고,
그래야 A/B/C 중 무엇이 맞는지 정해진다. 지금은 추측만 가능하다.

**P7이 먼저인 이유** — 대사가 바뀔 텐데 스크립트를 미리 박으면 두 번 일한다.

**지금 대비할 것** — 없다. 캐릭터 객체에 `scripts` 필드를 붙일 수 있게
열려 있으면 되고, 그건 저절로 된다.

부수 효과: API가 죽어도 게임이 돌아가고, 응답이 즉각적이라 타이밍 연출이
더 정확해진다.

## P9 · 언어 다양화

P1에서 문장을 데이터로 몰아뒀고 P4-1에서 다시 갈랐으므로 여기가 수월하다.
`strings.js`는 값이 전부 문자열이라 파일째 넘길 수 있다.

- UI 문자열(`strings.js`) / 콘텐츠(`content/`) / persona 세 층이 각각 대상
- persona는 번역이 아니라 **재작성**에 가깝다. 말투가 캐릭터의 본체라서
- 한국 관공서 문서 양식이 번역되면 무너지는 부분이 있다. 어디까지 현지화할지
  먼저 정할 것
